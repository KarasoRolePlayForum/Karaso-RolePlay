KARASO STAFF CONTROL CENTER V2

این نسخه پنل Owner و پنل شخصی Admin را از هم جدا می‌کند و به همان Supabase جدید متصل است.
Project URL: https://fagqwohtjdzmvkoeuwel.supabase.co
کلید عمومی Publishable داخل supabase-config.js باقی مانده است. هیچ service_role یا secret key در فایل‌های سایت قرار ندهید.

فایل‌های مهم:
- index.html: ورود و ثبت‌نام اعضای تیم
- owner.html: پنل اختصاصی Owner
- admin.html: پنل شخصی ادمین تأییدشده
- staff-list.html: فهرست ادمین‌ها با وضعیت فعال/مرخصی
- staff-console.js / staff-console.css: منطق و ظاهر پنل‌های جداگانه
- KARASO_STAFF_CONTROL_CENTER_V2.sql: مهاجرت دیتابیس برای نام بازی، تایم‌پلی جلسه‌ای و وضعیت مرخصی

مراحل نصب:
1) قبل از هر تغییری از فایل‌های فعلی GitHub یک نسخه پشتیبان نگه دارید.
2) وارد همان پروژه Supabase با آدرس fagqwohtjdzmvkoeuwel شوید.
3) SQL Editor > New query را باز کنید.
4) کل فایل KARASO_STAFF_CONTROL_CENTER_V2.sql را اجرا کنید.
5) اگر SQL بدون خطا اجرا شد، فایل‌های ZIP را در ریشه همان مخزن GitHub جایگزین کنید؛ پوشه redo را به عنوان ریشه سایت آپلود نکنید، محتویات داخل redo باید در ریشه مخزن باشند.
6) در Authentication > URL Configuration، آدرس سایت GitHub Pages و آدرس password-reset.html را در Redirect URLs نگه دارید.
7) سایت را باز کنید و با Owner فعلی وارد شوید. حساب Owner فعلی حفظ می‌شود؛ حساب جدید نسازید.

رفتار تایم‌پلی:
- ادمین پیش از ورود به بازی «شروع تایم‌پلی» و بعد از خروج «پایان تایم‌پلی» را می‌زند.
- ثبت شروع و پایان با RPC دیتابیس و زمان سرور انجام می‌شود؛ بستن مرورگر تایمر را متوقف نمی‌کند.
- Owner جلسات باز را می‌بیند و می‌تواند جلسه فراموش‌شده را ببندد.
- روز کاری از ساعت 03:00 منطقه زمانی Asia/Tehran محاسبه می‌شود. مجموع روزانه به شکل view محاسبه می‌شود و سوابق جلسه‌ها پاک نمی‌شوند.
- این سیستم حضور واقعی داخل گیم را خودکار تشخیص نمی‌دهد؛ تا وقتی اتصال به گیم‌مود یا API سرور بازی ساخته نشود، ادمین باید شروع/پایان را دستی بزند.

رفتار مرخصی:
- ادمین درخواست می‌فرستد.
- فقط Owner تأیید یا رد می‌کند.
- در فهرست ادمین‌ها، مرخصی تأییدشده در بازه زمانی خودش با وضعیت «در مرخصی» نمایش داده می‌شود؛ پس از پایان بازه، وضعیت خودکار به «فعال» برمی‌گردد.

نکات امنیتی:
- دسترسی Owner با role=owner و status=approved بررسی می‌شود.
- دسترسی ادمین فقط برای role=admin و status=approved است.
- کلید Publishable/anon برای مرورگر طراحی شده است؛ هرگز service_role یا sb_secret را در سایت قرار ندهید.

آزمایش انجام‌شده در زمان آماده‌سازی:
- بررسی ساختار ZIP و فایل‌های پروژه
- بررسی syntax فایل‌های JavaScript با node --check
- تست زنده روی حساب Supabase، ارسال ایمیل، اجرای SQL روی دیتابیس واقعی و تست مرورگر انجام نشده است؛ پس از اجرای مرحله 4 باید خطاهای احتمالی SQL را بررسی کرد.
